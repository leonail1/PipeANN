\begin{frame}[c]{需求 0：从 0 插入与小规模搜索}
    \centering
    \begin{columns}[c,onlytextwidth]
        \column{0.66\textwidth}
        \centering
        \includegraphics[width=0.98\linewidth,height=0.62\textheight,keepaspectratio]{../../experiments/flat_small_search/rss_latency_qps.png}

        \column{0.32\textwidth}
        \centering
        \begin{minipage}{0.98\linewidth}
            \tiny
            \raggedright
            \textbf{实现路径}

            \vspace{0.12em}
            空索引启动时进入内存 flat 模式；0--10k 向量直接插入内存数组并执行 exact KNN，不训练 PQ、不生成磁盘图。

            \vspace{0.12em}
            live count 超过 10k 后，再一次性 materialize 为磁盘图索引。

            \vspace{0.24em}
            \textbf{实验结果}

            \vspace{0.12em}
            SIFT1M 前 10k 向量实验中，10k 以内全部保持 flat mode。

            \vspace{0.12em}
            单查询 peak RSS 最高约 \textbf{32.3 MiB}，接近 30MB 要求。

            \vspace{0.12em}
            平均搜索延迟最高约 \textbf{0.20 ms}，显著低于 10ms 延迟要求；10k 附近 QPS 约 \textbf{5k}。

            \vspace{0.24em}
            \textcolor{red}{结论：已支持从 0 数据量开始插入，小规模阶段基本满足内存和延迟要求。}
        \end{minipage}
    \end{columns}
\end{frame}

\begin{frame}[c]{$\tau_m$ 标定与重新标定}
    \centering
    \scriptsize
    $\tau_m$ 是 prefilter 和 graph search 的切换边界；它不是固定常数，而是随索引状态重新校准。
    \vspace{0.55em}

    \begin{columns}[c,onlytextwidth]
        \column{0.56\textwidth}
        \centering
        \resizebox{0.98\linewidth}{!}{%
        \begin{tikzpicture}[
            scale=1.0,
            transform shape,
            font=\scriptsize,

            markline/.style={dashed, line width=0.55pt}
        ]

            \fill[purple!7] (3.10,0.48) rectangle (5.85,3.55);
            \draw[axis] (0.62,0.48) -- (6.02,0.48) node[below] {过滤选择性 $s$};
            \draw[axis] (0.62,0.48) -- (0.62,3.78) node[left] {Latency};
            \draw[curve, green!45!black]
                plot[smooth] coordinates {(0.75,0.75) (1.50,0.92) (2.25,1.28) (3.10,1.82) (4.25,2.70) (5.70,3.45)};
            \draw[curve, purple!70!black]
                plot[smooth] coordinates {(0.75,3.20) (1.55,2.72) (2.40,2.20) (3.10,1.82) (4.05,1.36) (5.70,1.05)};
            \draw[markline] (3.10,0.48) -- (3.10,1.82);
            \node[circle, fill=red!75!black, inner sep=1.5pt] at (3.10,1.82) {};
            \node[font=\bfseries\scriptsize, red!75!black] at (3.10,2.12) {$\tau_m$};
            \node[font=\tiny, green!45!black] at (5.08,2.72) {Prefilter};
            \node[font=\tiny, purple!70!black] at (4.95,1.44) {Graph search};
            \node[font=\tiny, green!45!black] at (1.75,0.82) {$s \leq \tau_m$};
            \node[font=\tiny, purple!70!black] at (4.70,0.82) {$s > \tau_m$};
        \end{tikzpicture}
        }

        \column{0.40\textwidth}
        \begin{minipage}{0.98\linewidth}
            \tiny
            \raggedright
            \textbf{标定方式}
            \vspace{0.15em}
            \begin{itemize}
                \item 对每个选择性 bucket 校准 $L$，只保留满足 recall 目标的点。
                \item 在这些点上比较 prefilter 与 graph search 的延迟曲线。
                \item prefilter 随选择性增大而变慢；graph search 反之。
                \item 两条曲线交点即 $\tau_m$：左侧走 prefilter，右侧走 graph。
                \item live count 漂移超过阈值时后台重标定；完成前使用旧 $\tau_m$，完成后原子切换到新 $\tau_m$。
            \end{itemize}
        \end{minipage}
    \end{columns}
\end{frame}
